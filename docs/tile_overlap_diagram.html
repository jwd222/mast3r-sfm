How tiling covers the image overlap — and where best-B-per-A matching can miss pixels

Two consecutive aerial frames are each cut into overlapping tiles, MASt3R is run on pairs of tiles, and the question is whether the whole ground-overlap gets matched. The default strategy --tile_pairing per_a matches each tile of image A to its single best-overlap tile in image B (B may be reused; no "stealing"). It is fast and near-complete, but it is not fully gap-free. The only fully gap-free option is --tile_pairing all (many-to-many), at ~3–4× the inference cost.

Key fact about the tiling (this is easy to get backwards): tiles within the same image overlap each other, not just at the edges. With tile 512 and overlap_px=128 the stride is 512−128 = 384, so every neighbouring pair of tiles shares a 128 px strip (the edge-aligned last tile shares even more). So B1 and B2 do overlap each other, and an A tile can straddle several B tiles at once.

1. The setup — two overlapping images, each fully tiled

Each frame is divided into a grid of overlapping tiles, so every pixel of each image belongs to at least one tile — the tiling is a complete cover. The two frames share a ground overlap region R (yellow). The diagrams below take a 1-D slice through R; the same logic holds in 2-D with more tiles.

2. The 1-D slice through the overlap (the key diagram)

Horizontal axis = world pixel position; only the overlap window R = [640, 1280] is shown. Two A tiles (A2, A3) and two B tiles (B1, B2) cover it. Because tiles overlap within each image, A3 straddles both B1 and B2.

Read the bottom two rows. per_a matches A2 and A3 each to their best B (= B1), so it covers [640…1152] but leaves a GAP at [1152…1280] — the right tail of A3 that only reaches B2, and (A3,B2) was not run. all also runs A3–B2, filling the gap, but at ~3–4× the inferences.

3. Zooming into the gap — why those pixels are missed

Pixels in [1152, 1280] lie in A3 only (Image 1) and B2 only (Image 2). Matching them requires the pair (A3, B2). But per_a chose A3's best overlap = B1, so (A3, B2) is never run → those pixels get no correspondence in this pair.

How to read these diagrams (pointers)

  1. Bars are pixel ranges. A3 [768…1280] means tile A3 spans those world pixels. Where an A bar and a B bar overlap in x is the region that tile-pair could match (the green A∩B bars).
  2. A matched pair only covers A∩B. Running MASt3R on (A,B) gives correspondences only for the slice where both tiles' footprints overlap — not all of A, not all of B.
  3. per_a = one B per A. Each A tile is matched to its single highest-overlap B (B may be reused). So A3, whose best overlap is B1, is run against B1 only — never B2. The part of A3 that lies over B2 ([1152…1280]) therefore has no pair covering it.
  4. The gap is a spill sliver. It appears wherever an A tile straddles a B-grid boundary and "spills" into a B tile it did not pick. With overlapping tiling that can happen at internal boundaries; the sliver is ~one tile-overlap wide (≤128 px).
  5. Only all is gap-free. It runs every (A,B) the two tiles overlap, so any point P (in some A and some B) has its pair run. Cost: ~3–4× more inferences, mostly redundant after dedup.
  6. Why per_a is still fine in practice. The same ground is matched in other image pairs (img1↔img3, …); with min_len_track=2 a point only needs to survive in one pair. Thin seam slivers are largely recovered across pairs.

Trade-off summary

StrategyCoverage of overlapTile inferencesWhen to use
--tile_pairing per_a (default) Every A tile matched to its best B; thin ≤128 px spill slivers can be unmatched in a given pair (recovered across pairs) ~1 per A tile (fast) Normal aligned strips; fast runs
--tile_pairing all Complete — every overlapping tile combination is matched (no gap) ~3–4× more (slow, mostly redundant after dedup) Only if a dataset shows visible holes / dropped seams
Practical guidance: keep per_a (the default). It matches your "one best B per A, no stealing" idea — fast, no dropped A tiles, and the residual seam slivers are recovered by cross-pair redundancy across the image graph. Switch to all only if a specific dataset shows visible holes/dropped seams in the reconstruction.
